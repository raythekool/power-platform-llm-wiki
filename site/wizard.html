You always need VS Code with GitHub Copilot, PowerShell 7 and git. Everything else depends on the sources you will use.

Step 1Passo 1

📦 Install the pluginInstalla il plugin

  1. In VS Code open Settings and enable Chat › Plugins: Enabled.
  2. In Chat › Plugins: Marketplaces add {{REPO_SLUG}}.
  3. In the Extensions view search @agentPlugins power-platform-llm-wiki and install.

Steps 1 and 2 are equivalent to this snippet in settings.json:

  1. In VS Code apri Impostazioni e attiva Chat › Plugins: Enabled.
  2. In Chat › Plugins: Marketplaces aggiungi {{REPO_SLUG}}.
  3. Nella vista Extensions cerca @agentPlugins power-platform-llm-wiki e installa.

I punti 1 e 2 equivalgono a questo frammento in settings.json:

settings.json 
"chat.plugins.enabled": true,
"chat.plugins.marketplaces": [
  "{{REPO_SLUG}}"
]

Using the terminal instead of VS Code? Install from the shell with GitHub Copilot CLI or Claude Code. In Claude Code the skills are called /power-platform-llm-wiki:init, :update and so on.

Usi il terminale invece di VS Code? Installa da shell con GitHub Copilot CLI o Claude Code. In Claude Code le skill si chiamano /power-platform-llm-wiki:init, :update e così via.

GitHub Copilot CLI 
copilot plugin marketplace add {{REPO_SLUG}}
copilot plugin install power-platform-llm-wiki@power-platform-llm-wiki
Claude Code 
claude plugin marketplace add {{REPO_SLUG}}
claude plugin install power-platform-llm-wiki@power-platform-llm-wiki

✅ Verify: in the chat, the agent list shows LLM Wiki.

✅ Verifica: nella chat, nell'elenco degli agenti compare LLM Wiki.

🚪 Start initAvvia init

  1. Open in VS Code the folder of the project repository, the one that will host the llm-wiki/ folder.
  2. In the chat pick the LLM Wiki agent.
  3. Type init.

The wizard first asks for the mode:

Recommended🧭 GuidedFirst time, or you do not know the configuration files.
📝 Self-serviceYou already know what you want: it creates a commented wiki.config.yml, you fill it in and then run config.

The rest of this page follows the guided mode.

  1. Apri in VS Code la cartella del repository del progetto, quello che ospiterà la cartella llm-wiki/.
  2. Nella chat scegli l'agente LLM Wiki.
  3. Scrivi init.

Il wizard ti chiede subito la modalità:

Consigliato🧭 GuidatoPrima volta, o non conosci i file di configurazione.
📝 Self-serviceSai già cosa vuoi: crea un file wiki.config.yml commentato, lo compili tu e poi lanci config.

Il resto di questa pagina segue la modalità guidata.

Step 3Passo 3

🏷️ Project and profilesProgetto e profili

The wizard asks: project name, content language, profiles.

  • Name: shown in the header of the published wiki. Example: Sales.
  • Language: it for Italian content (default), en for English.
  • Profiles: you can pick more than one.
power-platformDynamics 365 CE / Dataverse: plugins, PCF, web resources, flows, solutions.
dynamics-fnoFinance & Operations: tables, extensions, classes, data entities, security.
genericIntegrations, Azure Functions, APIs, .NET.

✅ Verify: the chosen profiles match what is really in the code. When in doubt pick the ones you need now: you can change them later with config.

Il wizard chiede: nome del progetto, lingua dei contenuti, profili.

  • Nome: compare nell'intestazione della wiki pubblicata. Esempio: Vendite.
  • Lingua: it per contenuti in italiano (predefinito), en per inglese.
  • Profili: puoi sceglierne più di uno.
power-platformDynamics 365 CE / Dataverse: plugin, PCF, web resource, flow, soluzioni.
dynamics-fnoFinance & Operations: tabelle, estensioni, classi, data entity, sicurezza.
genericIntegrazioni, Azure Functions, API, .NET.

✅ Verifica: i profili scelti corrispondono a ciò che c'è davvero nel codice. In caso di dubbio scegli quelli che ti servono ora: li cambi più avanti con config.

🔌 SourcesFonti

All sources are optional. The wizard proposes them one at a time: answer Yes only for those you have.

Source What it asks Notes
🧬 Code repository name, provider (azure-devops, github, local), URL, local folder, branch Recommended: the code is the primary source of the as-built documentation
📋 Azure DevOps Boards organization, project, areas and iterations (optional) Sign-in with your Microsoft account: no PAT needed
🗄️ Dataverse solution unique names, publisher prefixes Uses the active pacx auth profile: check with pacx auth ping
🏭 F&O metadata folders of the custom packages (e.g. <repo>/Metadata/<Package>) Do not list Microsoft standard packages
🐙 GitHub activity list of owner/repo Pull requests, issues, branches
📂 SharePoint site URL and libraries Documents must be downloaded into raw/ by hand

Example for a CE project on Azure DevOps

  • Code repository: name crm-solution, provider azure-devops, branch develop, local folder ../crm-solution.
  • Boards: organization contoso, project Sales.
  • Dataverse: solution SalesCore, prefix cts_.

Important: never write passwords, tokens or keys in the answers or in the configuration file. Access uses your account (Microsoft Entra ID, az login, pacx auth).

✅ Verify: for every repository the local folder exists (or will be cloned). For Dataverse, pacx auth ping replies.

Tutte le fonti sono facoltative. Il wizard le propone una per volta: rispondi Sì solo a quelle che hai.

📋 Azure DevOps Boards organizzazione, progetto, aree e iterazioni (facoltative) Accesso con il tuo account Microsoft: non serve nessun PAT

🌐 PublishingPubblicazione

The wizard asks: where to publish the wiki.

Most common🔷 Azure DevOps - project wikiThe wiki of the Azure DevOps project.Asks: organization, project, wiki name
🔷 Azure DevOps - code wikiThe wiki is a folder of a repository.Asks: repository, branch, folder
🐙 GitHub WikiThe project lives on GitHub.Asks: owner/repo
⏭️ NoneFor now you read the wiki only in VS Code.

Optional: a parent page (for example Knowledge Base) under which the whole wiki is mounted.

Note: automatic publishing without confirmation is off by default: before every push you see the changes and must confirm.

✅ Verify: you have the details to access the target wiki at hand (write permission included). You can also choose "None" and configure it later.

Il wizard chiede: dove pubblicare la wiki.

Caso più comune🔷 Azure DevOps - project wikiLa wiki del progetto Azure DevOps.Chiede: organizzazione, progetto, nome wiki
🔷 Azure DevOps - code wikiLa wiki è una cartella di un repository.Chiede: repository, branch, cartella
🐙 GitHub WikiIl progetto vive su GitHub.Chiede: owner/repo
⏭️ NessunaPer ora consulti la wiki solo in VS Code.

Facoltativo: una pagina madre (esempio Knowledge Base) sotto cui montare tutta la wiki.

Nota: la pubblicazione automatica senza conferma è disattivata per impostazione predefinita: prima di ogni push vedrai le modifiche e dovrai confermare.

✅ Verifica: hai a portata di mano i dati per accedere alla wiki di destinazione (permessi di scrittura inclusi). Puoi anche scegliere "Nessuna" e configurarla più tardi.

🛡️ GovernanceGovernance

The wizard asks:

Question Recommended Meaning
Redact personal data? Yes Only names and roles of participants are kept
After how many days is a page "stale"? 30 The lint flags pages not updated beyond this threshold
Who certifies the pages? first and last names Optional; tells who can declare a page "certified"

✅ Verify: you have at least one name for certification, typically a key user or a customer contact. The full process is in governance.md.

Il wizard chiede:

Domanda Valore consigliato Significato
Redigere i dati personali? Sì Dei partecipanti restano solo nomi e ruoli
Dopo quanti giorni una pagina è "vecchia"? 30 Il lint segnala le pagine non aggiornate oltre questa soglia
Chi certifica le pagine? nomi e cognomi Facoltativo; serve a sapere chi può dichiarare una pagina "certificata"

✅ Verifica: hai almeno un nome per la certificazione, tipicamente un key user o un referente del cliente. Il processo completo è in governance.md.

The wizard asks this only if the host repository is on GitHub.

To startweeklyAutomatic weekly update.
dailyUpdate every day.
manualNo automation: you update with update --full.

If you choose a schedule, the agent gives you the text to paste in Repository → Agents → Automations → Create new → On a schedule. If the repository is on Azure DevOps, skip this step and run update --full from VS Code when needed.

Sprint (Azure DevOps Boards only): length (default 2 weeks) and name format (YYYY-SNN).

Il wizard te lo chiede solo se il repository ospite è su GitHub.

Per iniziareweeklyAggiornamento settimanale automatico.
dailyAggiornamento ogni giorno.
manualNessuna automazione: aggiorni tu con update --full.

Se scegli una pianificazione, l'agente ti dà il testo da incollare in Repository → Agents → Automations → Create new → On a schedule. Se il repository è su Azure DevOps, salta questo passo e lancia update --full da VS Code quando serve.

Sprint (solo con Azure DevOps Boards): durata (predefinita 2 settimane) e formato del nome (YYYY-SNN).

✅ Confirm and verifyConferma e verifica

  1. The wizard shows a summary of the configuration and the list of files it creates or changes. Review it calmly.
  2. Answer Yes to proceed, No to cancel without writing anything.

At the end the project contains:

What What it is for
llm-wiki/wiki.config.yml Your choices (edit by hand or with config)
llm-wiki/raw/ Where you put FDD, TDD, minutes and other documents
llm-wiki/wiki/ The wiki itself (Markdown pages)
llm-wiki/.engine/ and AGENTS.md The engine managed by the plugin: do not edit
.vscode/mcp.json The Azure DevOps connection, if you use Boards
.github/copilot-instructions.md The instructions that make Copilot use the wiki

Final check (the agent runs it, but you can repeat it):

  1. Il wizard mostra un riepilogo della configurazione e l'elenco dei file che crea o modifica. Controllalo con calma.
  2. Rispondi Sì per procedere, No per annullare senza scrivere nulla.

Al termine il progetto contiene:

Cosa A cosa serve
llm-wiki/wiki.config.yml Le tue scelte (puoi modificarlo a mano o con config)
llm-wiki/raw/ Dove metti FDD, TDD, verbali e altri documenti
llm-wiki/wiki/ La wiki vera e propria (pagine Markdown)
llm-wiki/.engine/ e AGENTS.md Il motore gestito dal plugin: non modificarli
.vscode/mcp.json Il collegamento ad Azure DevOps, se usi le Boards
.github/copilot-instructions.md Le istruzioni che fanno usare la wiki a Copilot

Verifica finale (la fa l'agente, ma puoi ripeterla):

PowerShell 
pwsh llm-wiki/.engine/scripts/Test-WikiLint.ps1 -WikiPath llm-wiki/wiki

✅ Verify: the result shows 0 errors. Then commit the created files.

✅ Verifica: il risultato deve indicare 0 errori. Poi fai commit dei file creati.

🚀 Build the first wikiCostruisci la prima wiki

Choose based on the sources you enabled:

If you enabled… Tell the agent
🧬 Code update --source code
🗄️ Dataverse update --source dataverse
🏭 F&O update --source fno
📋 Boards update --source devops
📄 Existing documents copy the files into llm-wiki/raw/analysis/, specs/ or meetings/, then ingest raw/<folder>/<file>

When you are done:

  1. update --lint checks the quality (it must stay at 0 errors).
  2. query "how is the sales module built?" tries a question on the wiki.
  3. update --publish publishes, if you configured publishing.

Scegli in base alle fonti che hai attivato:

Se hai attivato… Scrivi all'agente
🧬 Codice update --source code
🗄️ Dataverse update --source dataverse
🏭 F&O update --source fno
📋 Boards update --source devops
📄 Documenti già pronti copia i file in llm-wiki/raw/analysis/, specs/ o meetings/, poi ingest raw/<cartella>/<file>

Quando hai finito:

  1. update --lint controlla la qualità (deve restare a 0 errori).
  2. query "come è fatto il modulo vendite?" prova una domanda sulla wiki.
  3. update --publish pubblica, se hai configurato la pubblicazione.

After the wizardDopo il wizard

Change your mind later.

Cambiare idea più tardi.

No need to run init again. Type config and choose what to change: sources, profiles, language, publishing, governance, automation. After a plugin update run config --refresh-engine, then update --lint.

Non devi rifare init. Scrivi config e scegli cosa cambiare: fonti, profili, lingua, pubblicazione, governance, automazione. Dopo un aggiornamento del plugin lancia config --refresh-engine, poi update --lint.

🩺 If something does not workSe qualcosa non funziona

The LLM Wiki agent does not appearL'agente LLM Wiki non compare

Check Chat › Plugins: Enabled and that the plugin is installed; restart VS Code.

Controlla Chat › Plugins: Enabled e che il plugin sia installato; riavvia VS Code.

pwsh not foundpwsh non trovato

Install PowerShell 7 and reopen VS Code.

Installa PowerShell 7 e riapri VS Code.

Cloning from Azure Repos keeps asking for credentialsIl clone di Azure Repos chiede le credenziali di continuo

Install Git Credential Manager and sign in with your account.

Installa Git Credential Manager e accedi con il tuo account.

Dataverse does not respondDataverse non risponde

Run pacx auth list and pacx auth ping; select the right profile with pacx auth select.

Esegui pacx auth list e pacx auth ping; seleziona il profilo giusto con pacx auth select.

Boards return no dataLe Boards non restituiscono dati

Check organization and project with config and make sure you have access to the project.

Controlla organizzazione e progetto con config e verifica di avere accesso al progetto.

The lint reports errors after initIl lint segnala errori dopo init

Read the error list (or the llm-wiki/wiki/lint-*.md report generated by update --lint), fix and run update --lint again.

Leggi l'elenco degli errori (o il report llm-wiki/wiki/lint-*.md generato da update --lint), correggi e rilancia update --lint.

You want to start overVuoi ripartire da zero

Run init again: it does not overwrite pages or documents already in raw/.

Rilancia init: non sovrascrive le pagine né i documenti già presenti in raw/.
